# Contributing

Thank you for your interest in OpenAusLMSK12.

## Ground rules

- Keep all architectural and implementation decisions in ADR format where possible.
- Update `docs/ADR_INDEX.md` when adding new ADRs.
- Preserve existing references and keep links validated.
- Prefer smaller, reviewable commits with clear scope.

## Development workflow

1. Fork and clone the repository.
2. Create a feature branch.
3. Add or update documentation artifacts and keep links consistent.
4. Run link checks in your local environment before submitting.
5. Open a pull request with clear context and rationale.

## Standards

- Use Markdown for planning and ADR documentation.
- Keep names clear and domain-scoped.
- Add source references for design statements where possible.

## Communication

Use issues for planning questions and PRs for concrete changes.
